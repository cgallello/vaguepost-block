Support

First run

  1. Open VagueBlock from the Chrome toolbar.
  2. Enable the extension and keep Blur & Review selected while tuning it.
  3. Enable Chrome's Prompt API flag at chrome://flags/#prompt-api. Older Chrome builds may also expose chrome://flags/#optimization-guide-on-device-model and chrome://flags/#prompt-api-for-gemini-nano; enable those when present, then relaunch Chrome.
  4. Choose Prepare local AI. Use chrome://on-device-internals to inspect model status if it remains unavailable.

Chrome requirements

Chrome's built-in model requires a supported desktop OS, at least 22 GB free on the volume containing the Chrome profile, and either 16 GB+ RAM with four CPU cores or a GPU with more than 4 GB VRAM. The one-time model download also needs an unmetered connection.

On newer Chrome builds, On-device Internals → Broker State may list the prompt_api use case as Not Supported and show no text-model asset. That is a Chrome rollout or build-capability limitation; VagueBlock cannot bypass it and will not send post text to a cloud service.

Actions

  • Reveal post restores a flagged post for the current session.
  • Not vague dismisses the flag without keeping its strike.
  • Allow prevents future classification/action for an account.
  • Block uses X's visible controls and is hidden when follow status is followed or uncertain.

If the King does not appear

Confirm the extension is enabled, the page is on x.com, the card is a quote-post, and local AI is available. X can change its page structure; VagueBlock records selector-health failures and fails safely rather than guessing.

Report a problem

Record the Chrome version, operating system, extension version, action mode, model availability, and the affected page. Do not send passwords, cookies, private messages, or real users' post text. A maintained support contact will be listed here before Store submission.
